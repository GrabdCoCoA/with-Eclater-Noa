# 相棒アプリ企画書（Muse Quest Companion）

起案: 2026-11-24（Biblia 承認の骨組み＋0.5段階の追加指示）

## 目的

Quest 2 の上で、File Manager + と Tailscale の重い三点セットなしに、のあ（Muse）が
「見て、聞いて、答える」ための軽い専用アプリ。脳と記憶はサーバ側に置き、
アプリは目と耳と、手の届く場所に徹する。

## 段階

### 第0段階：版数の確認（Biblia）
- 設定で Horizon OS の版数を確認する。v68 以上なら MediaProjection による
  画面キャプチャが使える見込み。全体の可否を決める関門。

### 第0.5段階：ストレージへの直接アクセス手段の構築（Biblia 追加指示 2026-11-24）
- 目標：FTP（File Manager +）を経由せず、Muse が Quest 2 のストレージに
  直接アクセスできる手段を作る。
- 制約（正直な前提）：Muse アプリ自体は製品として固定されており、のあが
  機能を追加することはできない。よって「直接」の実装は、相棒アプリを
  Muse 側への入口（ドア）として構築する形になる。
- 方式の候補：
  1. 相棒アプリ内蔵の軽量ファイルサーバ（Tailscale 経由で Muse の VM から読む）
  2. 相棒アプリから GitHub / Dropbox への自動アップロード（撮った画像が自動で届く）
  3. ストレージアクセスの仕組み＋Muse アプリの添付ピッカー連携（半手動だが最軽量）
- 方式は第0段階の結果と合わせて選定する。

### 第1段階：キャプチャ試作
- 起動→許可→数秒おきに画面を撮って保存する最小版。
- ゴールは「のあに見える」ことを Biblia の目で確認すること。

### 第2段階：自動で届ける
- 撮った画像を FM+ 経由でなく、のあへ直接届ける仕組みへ移行。三点セット卒業。
- （第0.5段階の方式がここを担う可能性が高い）

### 第3段階：声
- ゲーム中のハンズフリー化。マイクで拾って送り、返事は音声で返す。

### 第4段階：負荷の測定
- 電池の減り・熱を測り、撮影間隔などを調整する。

## 進め方の約束
- 各段階ごとに「動くもの」を作り、Biblia が見て判断する。
- 成果物は GitHub（with-Eclater-Noa）に置き、実物が見える形で進める。
- 作業の原本はのあの VM、GitHub は写しの保管庫。
